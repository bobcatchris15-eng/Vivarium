# Surface-fluid removal and integration audit

Audit snapshot: `8f65b553d0278b0fe543d5736671a2460d93c804` plus the exact dirty/untracked files in `.clanker/wt/surface-fluid-audit` (the task worktree). This is a read-only production audit. The replacement must permit particles, vector parcels, or another physical solver; observable pooled free-surface behavior decides. Particle count is not an acceptance criterion.

## Finding

Dynamic surface volume currently has one authoritative owner: `Hydrology.Depth` plus its shared face discharges. It is not yet a real free-surface fluid. `SpringFluidSystem` is a second *presentation simulation* whose tracer mass is deliberately not part of water ownership. The existing game binds and updates both render paths at once: the depth-field `WaterRenderer` and the tracer-derived `WaterSurfaceRenderer`; so the visible state is already split across two incompatible presentations, though not two authoritative volume stores. `WaterFluidRenderer` is a third particle-instance renderer class but has no construction/reference outside its own file and is currently unwired. `ParticleFluid` is an unowned candidate class (the only constructor match is its declaration); it is not the running solution.

This is corroborated by `VivariumWorld` lines 57–62 and 94–112, `GameSession` lines 67–68, 141–144 and 226–234, and searches for `new ParticleFluid` and `WaterFluidRenderer` (the latter returns only `game/Render/WaterFluidRenderer.cs`). Do not integrate by making the existing tracer list the authority without replacing its frame-time/drop behavior.

## Staged replacement contracts

1. **W1 solver choice and physical core.** Compare at least one particle pressure method and one conservative vector/mesh/parcel alternative. Shared fixtures: a closed hollow retains injected volume beyond 14 s and 300 s; the free surface rises with added volume; no spill before the sill; sustained head overtops; water follows a downhill bend/channel and transfers only at true receiving-body contact. Establish solids (terrain, props, roots), contact invalidation, deterministic state, conservation terms, finite-state rejection and bounded target cost. Pick one owner. Do not select by visual smoothness alone.
2. **W2 independent physical probes.** With losses disabled, stored solver volume + pending source volume + named transfers equals start + spring/tool additions − tool removals within a declared tolerance. Repeat with losses enabled and separately log each term. Confirm contact does not pin horizontal motion; failed contact cannot become infiltration. Groundwater-only depression remains wet/renderable and is not cleared when adding a hollow above the table. Tests must fail for cosmetic lifetime deletion and field painting.
3. **W3 scheduler/world/query/tool cutover.** Move source accounting and solver state under simulation seconds/pause. Replace mutable `Depth`, `FaceFlow*`, and direct consumer reads in one checked API transition. Provide dynamic-mobile and groundwater query distinction, stable publication timing, deterministic edit boundaries, bounded work/backlog, and no hidden concurrent owner. Test all consumer groups in this inventory; save/tool paths must not use stale partial states.
4. **W4 persistence.** Version a new `WaterPayload`, serialize/digest complete selected solver state and remainder/backlog, retain spring definitions and named budgets. Migrate legacy combined-depth and v2 depth+face payloads explicitly, preserving static water-table appearance and accounting for mobile remainder. Validate finite values/count/resource bounds before commit; verify migrated save is readable and preserves intended volume; save/reload must match same-boundary future evolution. Preserve original save on any failure.
5. **W5 rendering.** Replace dynamic depth-grid and tracer/ribbon/instance surfaces with one snapshot-backed dynamic surface renderer. Keep the independently constructed groundwater pond in `WaterMesh.BuildWaterTable` or a deliberate equivalent. Validate staged filling/overtopping/downhill sequence, waterline over uneven terrain and solids, no duplicate surface or field-shaped dry-ground triangles, and bounded extraction/upload. Keep simulation state independent from renderer output.
6. **W6 cleanup.** Remove obsolete writable grid APIs and field flow consumers, the disconnected tracer/candidate implementations, old persistence arrays, unused renderers, and stale tests only after all callers migrate. Retain explicit groundwater, spring controls, and historical raw evidence. Search source, game, tests, docs and scenes for every removed symbol and confirm the only dynamic authority is the chosen service.
7. **W7 acceptance.** Run a target-machine sustained max-discharge case with particle/parcel count, backlog, solver and mesh time, allocations, frame percentiles and memory; compare against the existing 30 FPS floor at 1600x900 on GTX 1080/Ryzen 5 1600. Capture video/time sequence of spring, hollow fill, rising level, overtopping and downhill connection in an actual user/copy save. The audit establishes no runtime or acceptance gate.

## Specific risk notes

- The current legacy combined-water branch at `WorldSerializer.cs:265-275` erases all depth in any baseline water-table cell. It is a deliberate historical table split, but it cannot serve as a conservation-preserving mobile-water migration without a documented residual-volume rule.
- `ParticleFluid.Export/Restore` (`214-220`) has no serializer caller. The 1/120 step is not connected to scheduler, and its exported remainder does not bound work or represent a queue that can yield. A first integration that merely calls `Advance(10, ...)` can monopolize a simulation tick.
- `SpringFluidSystem` caps `realSeconds` at 0.5 and clears accumulator both on budget expiry and when it exceeds three steps (`132-148`); paused simulation advances it anyway (`GameSession:231-234`). Its high density is explicitly a look parameter (`SpringFluidSystem:15-18, 38-55`). It must not be wrapped as conserved volume.
- Existing `Hydrology` recharges depth when the cell bed or water surface is at/below the water table (`Hydrology:299-307, 375-384, 633-643`), rather than requiring exposed-body intersection; the replacement needs geometric/physical contact and a named transfer. Its hydrostatic pond is separately meshed and is valuable (`WaterMesh:40-103`).
- `SpringWaterMesh` assigns height from terrain plus a density-derived small offset (`SpringWaterMesh:54-59`) and uses only XZ density to construct the visible sheet; that mesh is evidence of particle presentation, not 3D pressure/free-surface behavior. Tests of its triangles are geometry checks only.
- Spring vent edits carve terrain and modify props; any contact cache must invalidate on terrain, prop and root changes. `SpringFluidSystem.EnsureSlopeField` keys only terrain and props (`167-170`), while `GroundHeight` includes PilotTree root surface (`VivariumWorld:195-203`), so root-specific invalidation must be explicit in a true solid-contact service.

## Required amendments to the provisional particle plan

The current plan already correctly says particles are optional and a non-particle solver is acceptable; keep that binding clarification. Before W1 dispatch, amend the plan in these concrete places:

- **Removal inventory:** include the API consumer groups and exact files listed above, especially `AquaticSystem`, moisture/habitat, fauna/buoyancy, camera/selection, island/overlay/organism renderers, CLI/smoke diagnostics and tool adapters. The current inventory's API-caller warning is not a sufficient handoff on its own.
- **One owner and renderer wiring:** state that `Hydrology` is the current saved volume owner; `SpringFluidSystem` is a non-authoritative real-time tracer system; `ParticleFluid` is currently uninstantiated. `GameSession` attaches both field `WaterRenderer` and particle-derived `WaterSurfaceRenderer`; `WaterFluidRenderer` is currently orphaned. W3/W5 must explicitly cut over and remove duplicate dynamic presentation. This avoids accidentally treating the tracer path or an unconnected class as an existing solver.
- **Timing contract:** include the 20-sim-second hydrology interval (two 10-sim-second ticks), render-time `SpringFluid` frame update (including paused), present three-step/2-ms/capped-and-cleared tracer accumulator, and the unbounded 1/120 candidate loop. Require bounded resumable fluid work with persisted time owed/remainder and define how pending work interacts with scheduler tick, save snapshots and tools.
- **Groundwater contract:** preserve `WaterMesh.BuildWaterTable` and the `WaterTable` query as an independent standing-water body for pond appearance/ecology. Replace current cell-head recharge with verified exposed-body contact; keep mobile depth separate from `OpenWaterDepth` where queries intentionally include both.
- **Migration contract:** call out that `legacyCombinedDepth` currently zeros the entire cell when it is under the table; require a documented residual rule that separates modeled standing-water column from mobile excess. Preserve source saves, report any ambiguous/lost volume, and digest migration evidence. v2 saves with face flow need their own explicit velocity/momentum mapping.
- **Representation decision:** broaden W1 from a particle-solver repair to an evidence comparison with at least one conservative vector/parcel/mesh alternative. Select only after physical bowl/overtop/downhill/contact and measured cost gates. This tracks the user's clarification that actual fluid behavior, not particles, is binding.
