Defaults are `mobile_water_tint = (.10,.46,.50)`, `mobile_tint_strength = .13`, `mobile_reflection_strength = .035` and `mobile_roughness = .20`. A restrained colored albedo complements tinted transmission; the body tint increases gradually with optical depth. ## Ownership and architecture

`SurfaceFluidDynamics` owns all mobile water: supported-cell volume, shared face discharge, reconstruction slopes, airborne volume and physical time. The sparse 25 mm control volumes integrate eight triangles of actual solid support. Their free surface comes from conserved volume using a safeguarded Newton inversion of geometric capacity. Local-inertial face flow, donor limiting, wet/dry pressure and depth-based CFL substeps handle supported motion. Unsupported flow transfers into volume-carrying ballistic parcels; impact transfers it back, with a small conserved splash fraction. Parcels have no lifetime or camera-distance deletion.

`SurfaceLiquid` owns immutable terrain/prop/root snapshots, bounded jobs, immutable published views and queued input history. It integrates source rate changes within each physical step, preserving both intervals. Queued input survives saves and pause. Physics uses actual wall elapsed time in the client, including long rendering frames; calendar acceleration does not multiply the flow. A short, accounted five-second warmup uses this same owner for new presets. Explicit calendar-only `World.Step` remains an ecology operation; `SimHost` is the live physical-time entry point.

Persistent GPU tiles consume previous/current float textures. Their shared topology is subdivided for subcell support, not rebuilt as a CPU isosurface. Supported free surfaces respect ledges, solid boundaries and wet/dry coverage. CPU surface queries use the same reconstruction for habitat, contact and camera medium. GPU trajectory rings reconstruct connected falling sheets from real parcel volume, face aperture width and motion. Airborne refractors write depth so instanced sheet overlap cannot overwrite a nearer surface with a farther background copy. Connected runs remain sheets even when only two trajectory samples are present; only isolated samples and splash parcels become compact volume-preserving droplets. All rings, including the first ring, receive the same ballistic interpolation. Refraction, absorption, capillary normals and enclosure light response present the liquid.

The ecology scheduler has no advancing mobile-water solver. Hydrology's depth and current arrays are derived samples for ecology and overlays, plus historical import buffers. Tools, moisture, fauna habitat/current, observation, camera, presets and terrain editing use the new owner. Terrain/prop edits join outstanding work and invalidate solid support without deleting volume. Erosion still stops at its finite 3 cm / 600 second exposure budget; sediment deposition is not modeled.

## Visibility, continuity and motion follow-up

The user reported that moving water was difficult to see, separated into discrete pieces and looked slow. The mobile materials now use broader enclosure reflections, stronger moving refractive normals and a more visible thin-film edge. The standing-water material is not used to hide a junction. Supported topology now has six subdivisions per control volume (about 4.17 mm). A 2 mm reconstruction-error cutoff rejects stretched triangles; dry-owner extrapolation is bounded by local film depth so it cannot create a broad flap down a steep lip. CPU surface queries use the same wet-edge rule. Actual solid, wet/dry and ledge clipping remain.

Surface and falling-sheet optical time advances on every displayed frame and stops while paused. Two overlapping short advection intervals keep the highlight coordinates bounded. The previous expression multiplied local velocity/direction by total world age, creating stretched contour bands and aliasing as the flow field changed. The replacement transports the capillary pattern with local physical velocity and fades the coordinate resets continuously. It does not multiply the fluid clock or invent extra water.

Velocity diagnostics exposed a real query error at nearly empty cells: interpolated face discharge was divided by the remaining cell volume after outflow. This produced reported tail speeds above 200,000 m/s in a sloped fixture. Current now uses the actual wetted face sections retained from the discharge solve, with area-weighted interpolation. Those sections persist through current-format saves. The new regression checks bounded front velocity, nonzero downstream motion, conservation and identical render samples immediately after restore. The mature normal channel currently reports roughly 3.8 cm/s volume-weighted current and peaks near 62 cm/s; this includes slow retained pool volume.

Latest close-view evidence: `H-cohesive-motion` records a current-format populated world with 206 flora / 436 fauna at 10.54 biological days. Its 15-second native 1600x900 recording contains 450 frames at 30 FPS, decoded viewport match 2.17/255, average 104.51 FPS and p99 22.18 ms while externally recording. Fluid advanced 15 physical seconds in 15.0027 wall seconds; final backlog was 12.59 ms and conservation residual 6.64e-15 m3. Rare worst frame 164.95 ms is explicitly retained in the receipt.

`D-cohesive-motion` shows the controlled falling-water case: 449 native frames at 30 FPS, viewport match 2.20/255, 153.77 FPS / p99 13.20 ms / worst 27.26 ms while recording. The supported lip flap is removed, short connected runs stay connected, and a compact trajectory-area kernel removes independent parcel bulges while preserving its line-integrated volume. `D-owner-diagnostic`, `D-lip-projection` and `D-supported-edge-final` retain the diagnostic ownership, world-space probes and final support-boundary comparison.
Unsupported face sections now also retract toward round filaments instead of keeping their entire grid-face width throughout a fall. The presentation uses a Taylor-Culick edge-speed approximation, water/air surface tension 0.072 N/m and water density 1000 kg/m3; it preserves each parcel's represented cross-sectional volume. See [Taylor-Culick retractions and the influence of the surroundings](https://www.cambridge.org/core/journals/journal-of-fluid-mechanics/article/taylorculick-retractions-and-the-influence-of-the-surroundings/8F245EC9BB4BC42D887271686136D59A). This is a cross-section approximation, not a full viscous rim or transverse inter-stream coalescence solver. It does not move parcel centroids or alter authoritative inflow, timing or volume. The initial aperture and a fallen circular section are checked independently in the geometry regression.

## Reproduction

Run the game from the repo with the bundled Godot console executable and `--path game`. Build with `dotnet build game/Vivarium.csproj -v:q` first.

`./scripts/review-surface-water.ps1 -Scenario A -Mode Motion` runs a complete numerical/reload fixture and 8 Hz viewport samples. `-Scenario D -Mode Video` records an actual 30 FPS Desktop Duplication video of the owned foreground review window; requires FFmpeg and Python/Pillow for validation. `-Scenario H -Mode Benchmark -Preset default` tests the ordinary populated preset and deliberately fails the runner if the current performance target is missed. `-DurationSeconds` extends a live run. `-DisableMobileDrawing` runs an explicit drawing/performance control and is never ordinary visual acceptance. `-SavePath` accepts a copied current-format world for mature continuation; review saves go only into the new evidence directory. Evidence directories must be new; existing evidence is never overwritten by the runner.

The runner rejects missing receipts, failure markers, shader errors, conservation loss and sustained physical backlog. Benchmark mode also rejects average FPS below 30 or p99 above 33.333 ms. Video validation checks dimensions, frame rate, frame count, nonblank image and owned-viewport match. Visual quality still requires inspecting screenshots and actual decoded motion.

`./scripts/test-surface-water.ps1` runs the targeted fast regression, including the known baseline failures by default. `-ExcludeKnownBaselineFailures` explicitly excludes the three independently reproduced integration failures and reproduces the targeted passing run. The script rejects missing/empty receipts and any failed test.

Isolated test artifacts avoid an unrelated, pre-existing testhost that holds normal Debug outputs. See the exact filter and test receipts in the generated directory; exclude Speed=Slow for ordinary regression. No push or release was performed.
