# INT-L integration status

The accepted L1b A2 lighting experiment has not yet been integrated into the live world. The production renderer still uses stock lighting. No visual or performance claim is made for the work below.

An isolated CPU cache now accepts coalesced source updates and rebakes their affected regions. Its pending source count has a fixed capacity and producers must retry rejected submissions. A polled worker runs initialization, baking and packing off the Godot thread, with at most one batch in flight. Its completed CPU data can be uploaded by the GPU field on the Godot thread. Continuous, cycle-wrapping interpolation of the historical A2 ambient, bounce and exposure samples is available, but is not connected to the rig. The project frame cap is set to 30 fps.

Validation: an isolated test executable built against the current simulation sources passed `light.cycle`, `light.cache`, `light.occlusion`, and `light.worker`. The new tests check coalescing, capacity rejection, local occlusion, removal, one in-flight batch and snapshot size. The historical selftest project initially failed to compile because concurrent ecology work referenced interfaces still being developed; this is not a lighting test failure. No Godot process or GPU capture was run for this integration.

Remaining: wire an authoritative all-world source feed, including climber segments, terrain and props; run a bounded single worker with correct lifecycle and retry; bind materials and continuous rig values; validate Stock and Cached in the real game with day/dusk/night and local edits; and perform matched captures and soaks before choosing a default. FloraRenderer currently performs camera culling before computing actual mesh instances, so feeding it from its visible MultiMeshes would silently omit off-camera occluders. The existing A2 tables were calibrated for a different scene and fixed exposure and require recalibration in the actual world.

## Infrastructure review round 1

The review rejected the first version for starvation, world-swap lifecycle, and fault handling. Pending IDs now use explicit FIFO order; replacements retain their place and a full queue rejects new IDs for caller retry. Inputs are validated before acceptance. Worker initialization, deposition, invalidation and packing cooperatively observe cancellation, and a process-wide semaphore limits active cache work to one job. Disposal is nonblocking; `Quiescence` is the completion task for the discarded job. An asynchronous fault invalidates the cache: the caller must discard the worker and replay authoritative state into a new one. `Start` rejects nonpositive batch sizes synchronously. Texture creation failures now throw before the new texture is bound.

Red/green: the FIFO regression failed with `older coalesced source starved by new source` on the prior implementation, then passed after the queue change. The current isolated executable reports PASS for `light.cycle`, `light.cache`, `light.occlusion`, and `light.worker`. The tests cover sustained insertion with coalescing and retry, invalid indices, invalid batch size, disposal after initialization or batch scheduling, repeated swaps, an asynchronous allocation fault, and replay into a replacement worker. Scheduling means the test does not guarantee cancellation occurred inside a particular expensive loop. The tests do not prove the game controller uses this lifecycle correctly. Production acceptance still requires verifying cancellation and replacement during actual world swaps without accumulating work, and observing real texture upload. No GPU run has been made for this round.
